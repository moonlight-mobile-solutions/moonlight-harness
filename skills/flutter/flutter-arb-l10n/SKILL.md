# Flutter ARB Localization Skill

## Overview

Full internationalization via `flutter_localizations` + `intl`. Hardcoded user-facing strings are prohibited in production code: everything goes through `AppLocalizations.of(context)!`.

## Key Principles

1. **No hardcoded strings**: titles, labels, placeholders, tooltips, snackbars, button text all via `AppLocalizations`.
2. **Template locale first**: pick one locale (commonly `en`) as the template `.arb`; add new keys there first (with `@key` metadata), then translate into every other supported locale's `.arb`.
3. **Escape single quotes** in ARB values: `'` → `''` (e.g. `"Don''t have an account?"`), or ICU lexing fails.
4. **Regenerate after every `.arb` change**: `flutter gen-l10n`.
5. **Locale codes without region** where the framework's default resolution already does the right thing (e.g. `pt` resolves to `pt_BR` via `GlobalMaterialLocalizations`): only add a region suffix when you actually need to distinguish regional variants.

## File Structure

```
lib/l10n/
├── app_<template>.arb            # template locale
├── app_<other>.arb                # translated locale(s)
├── l10n.yaml                      # generator config (output-dir, etc.)
└── generated/                     # auto-generated by flutter gen-l10n
    ├── app_localizations.dart
    └── app_localizations_<locale>.dart
```

## ARB Syntax

### Simple key + mandatory description metadata

```json
{
  "loginTitle": "Sign in",
  "@loginTitle": { "description": "Title for the login page" }
}
```

### Escaping single quotes

```json
// ❌ "loginNoAccount": "Don't have an account?"
// ✅
"loginNoAccount": "Don''t have an account?"
```

### Placeholders

```json
{
  "loginWelcomeBack": "Welcome back, {name}!",
  "@loginWelcomeBack": {
    "description": "Welcome message for returning user",
    "placeholders": { "name": { "type": "String" } }
  }
}
```

### Plurals

```json
{
  "ordersCount": "{count, plural, one{1 order} other{{count} orders}}",
  "@ordersCount": {
    "description": "Number of orders",
    "placeholders": { "count": { "type": "int" } }
  }
}
```

## Usage in Widgets

```dart
final l10n = AppLocalizations.of(context)!;

Text(l10n.loginTitle);
Text(l10n.loginWelcomeBack('João'));
Text(l10n.ordersCount(42));
```

Cubits/Blocs don't have a `BuildContext`: pass `l10n`-resolved strings in from the widget layer (or via a callback), never resolve `AppLocalizations` inside a Cubit.

## MaterialApp Setup

```dart
MaterialApp.router(
  localizationsDelegates: AppLocalizations.localizationsDelegates,
  supportedLocales: AppLocalizations.supportedLocales,
  locale: const Locale('en'),
)
```

`AppLocalizations.localizationsDelegates` already bundles `AppLocalizations.delegate` plus the `GlobalMaterial/Widgets/CupertinoLocalizations` delegates.

## Workflow to Add a New String

1. Add key + value + `@key` description to the template `.arb`.
2. Add the translation to every other locale's `.arb`.
3. Run `flutter gen-l10n`.
4. Replace the hardcoded string in the widget with `l10n.keyName`.
5. Run the project's analyzer to confirm zero issues.

## Rules

- No hardcoded strings anywhere user-facing, including default text in reusable design-system components.
- Every key has an `@key` description.
- Escape single quotes.
- Regenerate after every ARB change and commit the generated files: they must stay in sync with the source `.arb`s.
